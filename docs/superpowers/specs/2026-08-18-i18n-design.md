# i18n design (en / ja / es)

**Date:** 2026-08-18
**Status:** Approved

## Goal

Add internationalization to `frontend/index.html` for English, Japanese, and Spanish, served as three distinct URLs (`/en/`, `/ja/`, `/es/`) so each language is individually indexable, with `hreflang` + canonical tags. The existing server-side template system (the `//$$VERSION_OPTIONS$$` replacement in `tileserver/src/main.rs::build_index`) is extended to render a per-language page at startup, using translation JSON files that can be edited without recompiling.

## Background / constraints (explored)

- Publishing flow: `frontend/index.html` is the source; `build_server.sh` copies it to `./tmp/index.html.tmpl`; the Rust tileserver reads the `.tmpl` from `DATA_PATH` at startup and `String::replace`s `//$$VERSION_OPTIONS$$` with the versions array. A single `index_html: Bytes` is served to everyone.
- All user-facing content lives in `frontend/index.html` (meta, labels, encart, export panel, context menu, alerts, dynamic JS strings) plus progress logs emitted from the compiled WASM (`frontend/src/lib.rs`) via the imported `log_user_message(s: &str)`.
- The site is at `https://wplace.eralyon.net/` (hardcoded canonical + og:url). Indexing matters, so the three languages must have distinct canonical URLs; single-URL content negotiation (Accept-Language only) would index poorly.

## Scope decisions

- Three languages: English (default), Japanese, Spanish.
- Distinct URLs: `/en/`, `/ja/`, `/es/`. `/` issues a 302 to the detected (Accept-Language) or default language. Unknown prefixes → 404.
- Server-side rendering: each URL's HTML contains real translated text (good for crawlers), not a JS-applied later.
- Translations stored as JSON files (`tileserver/i18n/{en,ja,es}.json`) read at startup from `DATA_PATH/i18n/`; editing copy requires only a server restart, no recompile.
- WASM export progress logs translate too, by turning them into keyed calls resolved in JS against the per-language dictionary.
- The debug-only decompress stats block (Decompress / Network / Process) is excluded from i18n; it stays as-is pending a debug flag elsewhere.

## Design

### Section 1 — Template extension (frontend/index.html + build_server.sh)

Placeholders added on top of the existing `//$$VERSION_OPTIONS$$`:

- `{{t:key}}` — inline translated text for HTML text content and attribute values (labels, placeholders, titles, aria-labels, meta content). Replaced server-side; output is the real translated string.
- `//$$I18N_DICT$$` — replaced server-side with `window.I18N = { ... }` containing the current language's strings for dynamic/format messages. Consumed by a JS helper `t(key, args)` and by `window.log_user_message`.
- `{{LANG_PATH}}` — current language path segment (`en` / `ja` / `es`), used in canonical/og:url.
- `{{HREFLANG_LINKS}}` — server-generated `<link rel="alternate" hreflang=...>` tags for en/ja/es plus `x-default` → `/en/`.
- `{{LANG_SWITCHER}}` — server-generated language switcher: three plain `<a href="/xx/">` links, active one highlighted; placed in the top `#version-select` bar.

`build_server.sh` additionally copies `tileserver/i18n/*.json` → `./tmp/i18n/`.

### Section 2 — Translation data (tileserver/i18n/{en,ja,es}.json)

Flat JSON maps, all three files sharing the exact same key set. Keys (≈35):

- **Meta:** `meta_title`, `meta_description`, `meta_keywords`. The `lang`/`<html>` code and canonical/og:url are **derived from the `Lang` enum in Rust** (`https://wplace.eralyon.net/{lang_path}/`), not stored in JSON, to avoid drift. `og:title`/`twitter:title` reuse `meta_title`; `og:description`/`twitter:description` reuse `meta_description`.
- **UI labels:** `version`, `zoom`, `lat`, `lng`, `zoom_ph`/`lat_ph`/`lng_ph`, `go`, `show_tile_overlay`, `export` (+`export_btn_title`), `close`, `close_encart`, `close_export_panel`, `static_png`, `animated_png`, `target_z`, `tile_bounds`, `min_x`, `max_x`, `min_y`, `max_y`, `start_date`, `end_date`, `zoom_in`, `zoom_out`, `toggle_art_opacity`, `download_tile`, `go_wplace_live`.
- **Encart:** `encart_p1`…`encart_p5` (links are placeholders in the HTML, not part of the string; the anchor text "murolem"/"GitHub"/"u/EralyonDotnet" and URLs are language-neutral and stay in HTML).
- **JS dynamic:** `export_z` (`z {0}`), `last_frame` (`Last frame: {0}`), `export_info` (`{0}×{1} tiles = {2} · {3}×{4} px`), `export_frames` (`{0} frames`), `too_large` (`Too large: {0} tiles (limit {1}). Zoom in or reduce the range.`), `exporting`, `done`, `export_failed` (`Export failed: {0}`), `cache_unsupported`, `tile_not_in_cache`.
- **WASM keys:** `downloading_tiles` (`Downloading {0} tiles…`), `downloading_url` (`Downloading {0}`), `download_finish`, `creating_image`, `creating_video`, `done`.

`{0}`, `{1}` are positional placeholders filled at runtime by `t(key, args)`. HTML-injected values use the raw strings (translations are controlled, no user input).

### Section 3 — Server (tileserver/src/main.rs)

- `Lang` enum `{En, Ja, Es}` with `path_of()`, `code()`, and `accept_language(&str) -> Lang` (first *supported* tag's primary subtag, skipping unsupported tags and `*`; none supported → `En`).
- Startup: load + validate the three JSON files (all keys present in all languages, else fail fast); then, for each lang, read `index.html.tmpl`, replace `{{t:key}}`, `//$$I18N_DICT$$` (serialize the lang's dict as the injected JS object), `{{LANG_PATH}}`, `{{HREFLANG_LINKS}}`, `{{LANG_SWITCHER}}`, and `//$$VERSION_OPTIONS$$`; abort startup if any `{{t:` placeholder survives. Store `index_html: HashMap<Lang, Bytes>`.
- Routes: `/en/`, `/ja/`, `/es/` → the corresponding page; `/xx` (no trailing slash) → 302 to `/xx/`; `/` → 302 to detected or default language; other prefixes → 404. `serve_index`/`serve_index_redirect` implemented with the existing axum router.

### Section 4 — JS wiring (frontend/index.html)

- Add `t(key, args)` helper: lookup `window.I18N`, replace `{n}` positional params; returns the key itself on miss.
- Replace hardcoded JS strings with `t(...)`: `z ${z}` option labels, `Last frame: ${endDate}`, the too-large hint, the export-info summary (`export_info`, `export_frames`), `Exporting…`, `Done.`, `Export failed: …`, the two cache `alert()`s, and the context-menu item labels.
- `window.log_user_message` becomes `async (key, args) => { … t(key, args) … }` so WASM progress renders localized.

### Section 5 — WASM keyed logs (frontend/src/lib.rs)

- Change the imported signature from `async fn log_user_message(s: &str)` to `async fn log_user_message(key: &str, args: Vec<String>)`; `Vec<String>` maps to a JS string array.
- Call sites become keyed: `downloading_tiles` (`vec![total_tiles.to_string()]`), `downloading_url` (`vec![url]`), `download_finish`, `creating_image`, `creating_video`, `done`.
- Deep error strings (e.g. `Failed to decode tile history: …`) inside returned `JsValue`s stay English within the localized `export_failed` wrapper — technical detail, not UI copy.

### Section 6 — SEO details

- Each page: `<html lang="{code}">`, `canonical` = `https://wplace.eralyon.net/{lang_path}/`, `og:url` likewise, and hreflang alternates for all three languages + `x-default` → `/en/`. `{code}` is the IETF tag (`en`/`ja`/`es`) and `{lang_path}` the matching URL segment.
- `/` 302 (not 301) so the redirect isn't cached permanently; default language `en`.
- Language switcher links are plain `<a>` — indexable, no JS.

### Section 7 — Error handling

- Missing `DATA_PATH/i18n/` dir or any language file → startup error.
- A key absent from any language → startup error naming the key and language.
- Leftover `{{t:` / `//$$I18N_DICT$$` / `{{LANG_…}}` placeholders after render → startup error.
- Unknown URL lang (`/fr/`) → 404 (existing `text_error` path).

## Testing & verification

Unit tests in `tileserver/src/main.rs` (or a small `i18n` test module):

1. Every key in `en.json` exists in `ja.json` and `es.json` (and vice-versa).
2. Rendered page per lang contains no leftover `{{t:` placeholders, correct `lang="{code}"`, correct canonical URL, and a known translated string.
3. `accept_language` mapping: `ja-JP,en;q=0.9`→Ja, `fr-FR,ja;q=0.8`→Ja (skip unsupported `fr`), `en-US`→En, `fr-FR`→En (none supported), empty→En.
4. Router: `/` + `Accept-Language: ja` → 302 `/ja/`; `/ja/` → 200 `lang="ja"`; `/fr/` → 404; `/en` → 302 `/en/`.
5. `build_index` fails fast (config error) when a JSON key is missing or files are absent — assert via a dedicated test fixture dir.

Manual verification: build with `build_server.sh`, run against `tmp/weeks`, check `/`, `/en/`, `/ja/`, `/es/` render, switcher works, export runs with localized progress logs.

## Production notes

- i18n is loaded at server startup, so after deploying new templates or dictionaries the server must be restarted.
- `build_server.sh` must be run while the server is stopped: it replaces the running binary.
